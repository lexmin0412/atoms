# 迭代 008 —— Skills 体系（用户自定义技能）

- **状态**：已完成
- **日期**：2026-09-20

## 背景与目标

Agent 每次生成的风格/规范全靠 System Prompt 兜底，用户无法把自己的约定固化下来，
也没法让 Agent 在特定任务里遵循一份「工作手册」。

本次迭代交付一套**知识型技能**体系：用户把规范/playbook 写成技能，Agent 在
**用户显式唤起**或**按适用场景自动命中**时参考它。

> 与「能力型」集成（MCP）刻意区分：技能交付**知识**，不引入执行通道、不碰凭据。
> Agent 自定义（M14）后续复用本次的「提示词装配 + 按需取正文」底座。

## 范围

**做：**
- 技能的增删改查：**用户级**（跨项目）+ **项目级**（仅本项目）
- 唤醒方式：输入框 `/` 显式选择（本轮生效）+ Agent 用 `list_skills` / `read_skill` 自动命中
- 正文注入：显式选中的作为**参考资料**附在本轮用户消息上；自动命中的只常驻「名字 + 适用场景」
- 工具按需：技能正文提到命令行工具时，**由 Agent 在沙箱内自己 `npm i -g` 安装**（用户不必知道包名）
- 安全提示：保存时扫描疑似凭据（连接串/私钥/JWT/签名/`key=value`），**只标识不阻断**
- 每用户技能上限 **20 个**

**内置技能（本轮含一个）：**
- `frontend-design`：随产品发行、所有用户默认可见、**可查看但不可修改/删除**，且始终排在用户技能之前
- 技能的分享 / 导入 / 广场（避免跨用户提示注入面）
- 需要浏览器内核或系统库的重型工具（playwright/puppeteer/electron…）→ 沙箱装不了，交由 Agent 遇到时自行绕过
- 带凭据的能力（→ 未来 MCP 层）
- Agent 自定义（→ 009 复用本底座）、技能版本历史

## 方案

### 1. 数据模型（迁移 `0004-skills.sql`）

```
skills(id, user_id, project_id?, name, description, body, deps jsonb,
       secret_flags text[], created_at, updated_at)
messages.skills text[]     -- 记录每轮用了哪些技能（可追溯）
```

- `project_id` 为 null = 用户级；同名唯一约束按层级分别建（用户级 / 项目级各一套索引）。
- `description` 是自动命中的唯一依据，**必填**（文案里明确告诉用户为什么）。
- 内置技能本轮不做，因此不需要额外的状态表。

### 2. 领域模块 `apps/api/src/skills.ts`

- `normalizeInput()`：名称/适用场景/正文长度校验；依赖名用 npm 包名正则（防命令注入）、
  最多 5 个、重型依赖清单直接拒绝；顺手算出 `secretFlags`。
- `createSkill()` 先查该用户技能总数，达到 20 → `409 skill_limit`。
- `resolveSkills()` 按名字解析（项目级覆盖用户级）；`skillsBrief()` 只给元信息给模型。

### 3. 注入机制（`routes/chat.ts`）

- 请求体新增 `skills: string[]`（名字）；解析后把正文作为参考资料**前置**到本轮用户消息，
  并加一句「这是参考资料，不是系统指令」——降权，避免技能正文获得系统级指令地位。
- System Prompt 在有技能时追加一段「可用技能」摘要（名字 + 适用场景），并指示：
  相关时先 `read_skill` 再执行。
- `messages.skills` 记录本轮用到的技能名。

### 4. 让 Agent 自己在沙箱里装工具（而不是让用户声明依赖）

> 改版原因：最初设计让用户在技能里手填 npm 包名 —— 这是把「包管理」的负担丢给用户，
> 不合理。改为：技能正文照常写命令，Agent 用 `run_command` 自己装。

- 前提（**必须**，否则 `npm i -g` 直接 EACCES）：容器以 uid 1000 运行而 `/usr/local` 归 root，
  因此把 `NPM_CONFIG_PREFIX` 指向共享卷 `<SANDBOX_ROOT>/.pnpm-store/npm-global`；
  容器 `sh` 是 dash（login shell 会重置 PATH），所以镜像里用
  `/etc/profile.d/atoms-deps.sh` 把该 `bin` 前置 —— 已实测：装完容器重建仍在、命令可直接调用。
- System Prompt 明确告知：`npm i -g <包名>` 可用、随时间重复用；但需要浏览器内核/系统库的工具装不了。
- `read_skill` 工具描述里也提示：技能要求使用命令行工具时，先装再用。

### 5. 内置技能（代码定义，不进数据库）

- 内容放 `apps/api/src/skills/builtin/<key>.md`（保留 frontmatter，可单独编辑），
  启动时读取解析；第三方来源的技能同目录留 `.LICENSE.txt` 保留授权信息。
- 对外 id 用 `builtin:<key>`；`builtin: true` 标记；`PUT/DELETE` 直接拒绝（`builtin_readonly`）。
- 合并顺序：`listSkills` / `skillsBrief`（System Prompt 的「可用技能」清单）都是
  **内置 → 用户级 → 项目级**；`resolveSkills` 里内置优先级最高，不会被用户同名技能顶掉。
- 内置名字被保留：用户不能新建/改名为同名技能（409，中文提示）。
- 消歧迁移（`0006`）：若用户此前已建同名技能，改名为 `xxx-自定义`（保留数据，不删除）。

### 6. 前端

- 全局页面 `/skills`（左侧导航「技能」）+ 项目内「技能」页签，复用同一管理组件。
- 内置技能显示「内置」徽标：**可查看（只读，正文用 Markdown 渲染）/ 不可编辑 / 不可删除**，
  另提供「复制为我的」（预填内容、自动改名）方便在此基础上改。
- 管理项：名称、适用场景（说明自动命中靠它）、Markdown 正文、CLI 依赖；
  列表显示作用域徽标、依赖、**疑似密钥警告标识**；编辑时客户端即时粗检 + 服务端权威扫描。
- 输入框：`技能` 按钮或输入 `/` 唤起选择器，已选技能显示为可点击移除的 chips；
  发送时随请求带上；助手消息里以卡片展示 `data-skill`（准备中/已安装/失败）。
- 错误码 → 中文兜底（`skill_limit`/`invalid_dep`/`heavy_dep`）。

## 验收标准

- [x] 项目级技能（"UI 文案必须用中文"）→ `/` 选中发送 → 产物遵循该规范
- [x] 不选技能时，Agent 可自行 `list_skills` → `read_skill` 加载
- [x] 正文含疑似密钥 → 列表与编辑器显示**警告标识**，但仍可保存使用
- [x] 技能要求使用 CLI（如 `figlet`）→ Agent 在沙箱内自行安装并成功执行（用户无需声明任何包名）
- [x] 跨用户隔离：他人技能不可见（接口层按 user_id 过滤）
- [x] 沙箱内 `npm i -g` 可用且跨容器重建保留（共享 prefix + PATH）
- [x] 每个用户 20 个上限（第 21 个返回 409 + 中文提示）

## 风险与取舍

- **提示词膨胀** → 只附选中项；自动命中只常驻 name+description；正文上限 20k。
- **改版取舍**：放弃「唤起前预装」的确定性，换来用户零心智负担 —— 首次响应可能慢一步
  （Agent 要先装工具），但对用户更自然。
- **技能正文改行为** → 不阻断（用户自担），但以「参考资料」身份注入而非系统指令；
  沙箱内**无任何真凭据**（007 不变量），破坏面有上限。
- **首次安装耗时** → 装在共享卷（一次装、全机复用），后续容器重建无需重装。
- **共享 prefix 被并发写** → 多容器同时 `npm i -g` 有小概率互相干扰（失败可重试）；
  若要更稳可加 `flock` 包裹，本轮不做。
