# 迭代 006 —— 品牌化与视觉体系重构

- **状态**：已完成
- **日期**：2026-09-20

## 背景与目标

当前 UI 是一路功能优先堆出来的：裸 Tailwind 灰阶、散落的类名、无品牌识别、各页面间距与字号不统一——一眼就能看出是功能优先堆出来的产物。
本迭代做**品牌化与视觉体系重构**，把它做成**生产级**观感：统一的 token、双主题、蓝图网格背景、真正的字标，并重排页面元素。

## 澄清结论

| # | 决策 |
|---|---|
| 1 | 品牌名 **Atoms**（不变；域名/证书/COS 全部沿用，零迁移成本） |
| 2 | **双主题**（亮/暗），跟随系统 + 手动三态（系统/亮/暗）切换并持久化 |
| 3 | 背景走**蓝图网格**：正交 1px 细线 + 顶部柔和辉光，明暗各一套 alpha |
| 4 | 强调色**电子青（electric cyan/teal）**，另配 amber 作高亮；语义色（success/warn/danger）与强调色**分离** |
| 5 | 字体**全部自托管**（npm → `public/fonts/`，同源，不依赖任何外部字体 CDN） |
| 6 | 范围：**全部用户端页面**；抽 `styles/tokens.css` + `components/ui/` |

> 字体说明：`next/font/google` 那种「构建期拉 Google」的坑天然不存在——我们只用 npm 包 + 本地 `@font-face`，
> 构建与运行都不发外部字体请求；`font-display: swap` 保证慢加载时先渲染系统字、不白屏。

## 方案

### 1. 字体
| 用途 | 字体 | 来源 | 体积 |
|---|---|---|---|
| 拉丁/数字 | **Geist Variable** | `@fontsource-variable/geist` | ~180 KB |
| 等宽（代码/数字/行号） | **Geist Mono Variable** | `@fontsource-variable/geist-mono` | ~172 KB |
| 中文 | **Noto Sans SC Variable** | `@fontsource-variable/noto-sans-sc` | 4 MB，但**按 `unicode-range` 分 ~100 片**，浏览器按需下载（单页通常 100–300 KB） |

- 字体栈：`Geist → Noto Sans SC → system-ui`（Geist 无 CJK，中文自然落到 Noto）
- 余额/时间/行号统一 `tabular-nums`

### 2. 设计 token（`apps/web/src/styles/tokens.css`，Tailwind v4 `@theme`）
- 颜色：**oklch**，`--background / --surface / --elevated / --foreground / --muted-foreground / --border / --accent / --ring / --success / --warn / --danger`
- 主题：`:root`（Blueprint Paper 亮）/ `.dark`（Blueprint Night 暗）；`color-scheme` 同步
- 网格：`--grid-line` + 一个 `.blueprint-bg` 工具类（两条正交 `linear-gradient` + 顶部径向辉光）
- 圆角收敛（6/8px 级），间距走 4px 栅格；阴影克制（描边为主、阴影为辅）

### 3. 品牌
- **字标**：`Atoms` wordmark（定制字重/字距）+ 几何「原子/点阵」符号（内联 SVG，与网格同构）
- 语气：精确、工程感；文案统一（空态/加载/错误）

### 4. 结构与组件
- 新增 **`AppShell` 全局外壳**：顶栏 = 字标 · 项目面包屑 · 积分 · 主题切换 · 用户菜单
- 抽 `components/ui/`：`Button`（primary/ghost/outline/danger，尺寸档）、`Badge`、`Card`、`Segmented`、`Field`、`Logo`、`Tooltip`
- **登录页**：品牌化（字标 + 网格 + 极简表单）
- **项目列表**：卡片栅格 → **行式列表**（名称/状态徽章/时间 + hover 操作），去掉卡片堆叠的「模板感」
- **工作台**：
  - 保留左右可拖拽分栏与「工作台在左 / 对话在右」
  - tab → `Segmented` 控件；面板头统一
  - 对话**去气泡**：用户消息用左侧标线 + 弱底色，助手消息用编辑式排版（贴近文档/IDE 的输出感）
  - 工具卡 / 终端块统一为「**图纸卡**」：细描边 + 等宽标题行 + 折叠
  - 空状态：示例以网格卡片呈现
- **积分页**：指标卡（余额/本期已用/月额度）+ 流水表格精修
- 统一 skeleton / 空态 / 错误态

### 5. 可访问性与质量
- 文本对比度 ≥ 4.5:1（含 muted 文本）
- 统一 `focus-visible` 环（用 `--ring`），键盘可达
- `prefers-reduced-motion` 下关闭非必要动效

## 风险与取舍

- 改动面大 → **逐页推进、逐页截图确认**，不满意可随时叫停回退。
- CJK 字体体积 → 已由 `unicode-range` 分片消化；再加 `font-display: swap` 兜底。
- 蓝图网格属强风格元素 → 用低 alpha + 只在背景层，避免干扰内容阅读。
- 不引入 UI 库（保持零新增运行时依赖），用 token + 少量基础组件自建。

### 调整：以产品自身 UI 为基准重做一版（006b）

首版上线后对照同类产品的实际界面复盘，发现「专业感」主要不来自配色，而来自**结构**。据此调整（同迭代内，不新开）：

| 项 | 首版 | 调整后 |
|---|---|---|
| 骨架 | 顶栏 + 大片留白 | **左侧固定导航**（个人空间 / 首页·积分 / 最近项目 / 底部主题与用户），可折叠并持久化，主区浅底 |
| 项目列表 | 单列行式 | **16:10 缩略图卡片栅格**（真实截图缺失时用按 id 派生的确定性占位：品牌点阵 + 暖色晕） |
| 强调色 | 淡青（偏冷、大面积铺） | **橙底白字**（`oklch(60% .19 42)`，hue 45 非偏黄），小面积点睛（主按钮 / 激活态 / 焦点环 / 发送键）；语义色独立 |
| 预览 | 裸 iframe | **应用查看器**：浏览器 chrome（窗口点 / 锁定图标 + 地址胶囊 / 刷新 / 外链）包在大圆角容器里 |
| 对话 | 纯文本段落 | 助手消息带**操作行**（复制 / 重新生成）与**来源 chip**；composer 内嵌**积分剩余** + 圆形发送 |
| 配色基调 | 冷灰 | **暖中性**（纸感亮 / 暖黑暗），配色整体更接近单色，靠留白与层级撑质感 |

同时修了一处结构性缺陷：工作台宽度基准原来用 `window.innerWidth`，被侧栏包裹后不再等于容器宽；改为由 `ResizeObserver` 量容器，并给外壳主区补 `min-w-0`（否则 `flex-1` 的 `min-width:auto` 会被内容撑破导致横向溢出）。

### 复盘的四处修正

1. **侧栏折叠后无法展开** → 折叠态补「展开侧栏」按钮（折叠宽 64px，容纳 mark + 按钮）。
2. **强调色偏黄、观感像某站** → 色相从 78（偏黄橙）移到 **45（偏红橙/朱橙）**，并降低明度、提高饱和：仍是橙色，但明显不是 #FF9000 那个橙。
3. **三处头部高度不一致** → 侧栏头部 / 工作台头部 / 对话头部统一 **48px**。
4. **项目详情页功能位置** →
   - 工作台头部：**左侧项目名 + 预览/文件/数据库**，右侧「刷新 · 发布」
   - 对话头部：标题改 **Chat with me**，右侧放**积分余额**
   - 积分组件只留**图标 + 余额**（去掉周期额度，用户不关心）

### 再一轮修正

1. **橙底黑字不搭** → 改为**橙底白字**（对齐参考的做法）。因此把橙色明度压到 **0.60**（亮）/ **0.64**（暗）以保证白字对比度（≈4.5:1+）；`--accent-ink` 同步加深用于文字/图标。
2. **折叠时展开按钮挤压 Logo** → 折叠态头部只留品牌 mark；**展开按钮浮到主区左上角**（`absolute`，48px 头部对齐位置），并通过 `--nav-overlay` 变量让工作台头部左内边距自动让位，避免压住项目名。
3. **折叠态底部可用性**：
   - 主题切换由三键组改为**单键循环**（系统 → 亮 → 暗），64px 内完整可见；
   - 头像按钮**不再直接退出登录**（原实现是 bug），改为弹出用户菜单（向右展开）。

### 再一轮细节修正

1. **折叠态头像未水平居中** → 紧凑模式的按钮补 `w-full`（此前只有 `justify-center`，按钮宽度退化成内容宽）。实测 `avatarCenter == asideCenter`（diff 0）。
2. **积分徽标点击直跳** → 改为 **Popover**：展示余额 / 本周期已用 / 每月额度，**明细入口在 Popover 内**（点击才跳转）；支持点外部与 Esc 关闭。
3. **工作台头部** → 移除「刷新」（预览区浏览器 chrome 已有刷新按钮）；「发布」按钮放大（`h-8 / 13.5px`）。

### 文件管理器的降噪与对齐

1. **同一垂直区域堆三个操作按钮，太密** → 新增 `ui/IconButton`（图标 + 自绘 Tooltip，hover 出文字、支持左/下两个方向）。**保存**、**重新加载**、**重新构建** 全部降级为图标；仅保留 `+ 文件 / + 目录` 为文字按钮。
2. **文件树缩进/图标不像 VSCode** → 新增 `ui/FileIcon`：
   - 目录：**chevron（旋转过渡）+ 文件夹图标**；文件：占位槽 + **文档图标**
   - 文档图标**按扩展名着色**（ts 蓝 / tsx 天蓝 / js-json 黄 / css 紫 / html 红 / md-yaml 灰）
   - 行高 22px、每级缩进 10px、字号 12.5px，去掉原来的等宽文字徽标（`TS` / `{}` / `<>`）

### 主操作补齐图标

新增 `ui/icons.tsx`（内联 SVG 图标集，不引图标包），给**重要操作**配图标：

| 位置 | 图标 |
|---|---|
| 新建项目 / 创建 | `+` |
| 发布 | 火箭 |
| 登录 / 注册并登录 | 箭头 → |
| 文件 / 目录（新建） | 文件+ / 文件夹+ |

次级操作（取消、确定、翻页、刷新等）保持纯文字，避免图标泛滥。

### 发布文案 / 数据库视图 / 应用图标

1. **发布总提示「首次安装依赖」** → 根因是 `startRelease` **每次都会重建容器并 `pnpm install`**，而前端文案写死「首次」。改为后端返回 `firstTime`（是否已有 `app_releases` 记录），前端据此显示：首次「首次发布，正在安装依赖并启动…」，否则「正在启动应用…」。*（依赖装在共享 pnpm store 里，后续发布实际很快）*
2. **数据库视图** → 左侧表名加**表图标**（并显示行数）；右侧顶部改为 **[数据 | 字段]** 切换（**数据默认选中**）；「字段」页签用表格展示 字段 / 类型 / 约束（可空、非空徽章）+ 总数，替换原来挤在头部的字段列表。
   - 顺带修：`dbAvailable` 原来只在生成结束后探测，导致已有数据库表的项目进页面看不到「数据库」页签 → 改为**挂载时也探测**。
3. **默认应用图标** → 在 System Prompt 中强制：**每次新建项目必须生成 `apps/web/public/icon.svg`**（原创几何标识、`viewBox 0 0 64 64`、不用文字、明暗背景都可辨、不照搬品牌），并在 `index.html` 引用为 favicon；用户要求时改同一文件。
   - 新增 `GET /api/projects/:id/icon` 返回该 SVG；首页卡片优先展示它，缺失时回退品牌占位图。

### 关键操作二次确认

新增 `ui/confirm.tsx`：`PopConfirm`（内联气泡，接管触发元素的 onClick，确认后才执行）、`ConfirmDialog`（模态，用于菜单场景）、`PromptDialog`（受控输入弹窗）。

| 操作 | 处理 |
|---|---|
| **发布** | `PopConfirm`：说明「将发布为独立应用，可随时下架」 |
| **下架** | `PopConfirm`（危险样式）：说明「线上链接将立即不可访问」 |
| **删除项目** | 原生 `window.confirm` → `ConfirmDialog`（列出影响：源码 / 数据库表 / 已发布应用） |
| **删除文件 / 目录** | 原生 `window.confirm` → `ConfirmDialog`（目录会提示级联删除） |
| **重命名项目** | 原生 `window.prompt` → `PromptDialog` |

顺带修：`Button` 新增 `danger-solid` 变体。此前用 `className` 覆盖 `bg-muted` 会与变体类冲突（Tailwind 输出顺序决定胜负），导致确认按钮几乎不可见。

另外：左侧导航已有「积分」入口，**左下角用户菜单移除「积分明细」**，只保留「退出登录」。

### 与计划的偏差

1. 额外修了一处既有缺陷：`ProjectDto` 声明 camelCase 但接口返回 snake_case（`updated_at`），在 `api.ts` 增加归一化。
2. 工作台在全局外壳之下再带一条「项目条」（标题 + 生成状态 + 移动端切换），而非把标题塞进外壳工具区——避免跨层传递状态。
3. 积分徽标改为事件驱动刷新（`atoms:credits`），不再由 Chat 向下传 `refreshKey`。
